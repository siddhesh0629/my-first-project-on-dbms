# Warehouse Management System (WMS)

An academic **DBMS project** built with **PHP, MySQL, HTML, CSS and JavaScript** for managing computer-hardware inventory across warehouses.

## Features

- Role-based access: **ADMIN**, **STOCK_MANAGER**, **USER**
- Product, category, supplier, warehouse, and stock management
- Order and customer records
- Stock movement audit logging using MySQL triggers
- Dashboard and inventory reports

## Database design

`database.sql` creates the `warehouse_db` database with 10 tables:
`users`, `categories`, `suppliers`, `warehouses`, `products`, `stock`, `customers`, `orders`, `order_details`, and `stock_log`.

Audit triggers: `trg_stock_insert`, `trg_stock_update`, and `trg_stock_delete`.

## Run locally

1. Install **PHP** with the `mysqli` extension, **MySQL**, and a local web server such as XAMPP (Apache).
2. Put this folder in your web server's document root (for XAMPP, usually `htdocs/wms_github_ready`).
3. In MySQL Workbench, import/run `database.sql`. **Warning: the script drops and recreates the project's tables; back up existing data first.**
4. Check `config/db_connect.php`. Defaults: `localhost`, `root`, empty local password, database `warehouse_db`, port `3307`. Override with `WMS_DB_HOST`, `WMS_DB_USER`, `WMS_DB_PASSWORD`, `WMS_DB_NAME`, and `WMS_DB_PORT` environment variables if needed. `.env.example` is only a reference; PHP does not automatically load it.
5. From a terminal in this folder, run `php setup_users.php` to create three demonstration accounts with **your own passwords**. Password input is visible in the terminal; run it privately. The script replaces passwords for existing demo usernames.
6. Start Apache and MySQL, then open `http://localhost/wms_github_ready/` (adjust the URL to match your folder name).

## Security notes

This is an **academic demonstration**, not a production-hardened application. The login code supports both hashed and legacy plaintext passwords for compatibility; use only hashed passwords (as generated by `setup_users.php`) and remove the legacy fallback before production deployment. Do not upload real credentials, private customer data, or a production database dump.
